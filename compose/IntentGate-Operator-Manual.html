How IntentGate works, briefly

IntentGate is a gateway between your AI agents and the tool/MCP servers they call. Every call passes four checks — capability (does the token allow this tool), intent (does the call match the agent's stated purpose), policy (your Rego rules), and budget (spend and rate limits) — and every decision is written to a tamper-evident audit log. The console is how you manage all of it; the gateway enforces on its own and keeps running even if the console is down.

Govern your agents

Agents viewer

The inventory of every agent IntentGate knows about — those routed through the gateway and those surfaced by passive discovery. Clickable metric cards (total, on gateway, shadow, flagged) filter the table; search and filter chips handle scale. Each agent shows its owner, applied policy, status, and OWASP risk badges. From a row you set the owner, apply a policy, Set up (route it), and attest.

Discovery sources admin

Connect your existing tools — CASB (Zscaler, Netskope), proxy, DNS (Infoblox), cloud, IdP, CMDB — so agents calling tools outside the gateway surface as shadow AI. Sources can push to the ingest endpoint or be pulled on a schedule; you can also import a CSV/JSON to seed the inventory.

Policy gallery admin

The friendly front door to policy. Open it for an agent and it recommends a policy matched to that agent's risk signals; Apply scopes it to the agent as a draft. Need something bespoke? Request a custom policy and the IntentGate team writes it for you — you keep control of what ships.

Policies admin

The engine room: the live Rego rulebook the gateway enforces. View the active policy, edit raw Rego for cases templates don't cover, and — the key safety feature — dry-run a draft against historical audit to see exactly what it would have allowed or blocked before publishing. Publishing hot-reloads the gateway within a second; no restart. A baseline floor applies to all agents (destructive tools blocked, money-movement capped) so nothing is wide open while you work.

Attestation viewer

Owners re-confirm their agents on a cadence — your evidence that someone is accountable. Because confirming hundreds one-by-one doesn't scale, run an attestation campaign: scope it, and every owner gets their own queue to clear. Works with no IGA, and is ready to sync when you have one. Owners must be a company-domain email (enforced).

Reports viewer

Governance reports — posture, access register, attestation status, and decision activity — viewable here and downloadable as CSV / JSON. A read-only REST API serves the same data for automated pulls.

Setup admin

The no-code wizard. Answer a few questions (platform, topology single vs HA, tool server, database) and it generates the exact deploy config, routing snippet, and lockdown settings to copy — including the load-balancer configuration to apply on your own LB when you choose high availability.

Daily operations

Dashboard viewer

Live overview: decision volume over time, allow vs block rate, and the top blocking reasons — your at-a-glance health.

Tokens viewer

Mint, revoke, attenuate, and inspect agent capability tokens. A token scopes which tools an agent may call; attenuation narrows an existing token without re-issuing.

Audit viewer

Every decision, filterable by agent, tool, decision, and time. Drill into a row for the full request, the matched rule, and the reason. Export bundles for evidence.

Audit verify admin

Proves no audit event was silently deleted or altered. "Verify chain" walks the per-tenant hash chain and reports integrity, count, time range, and the chain-head signature. Run it monthly and after any incident.

Approvals viewer / operator

When a policy escalates a call to a human, it lands here for approve/deny — optionally surfaced into Slack/Teams via ChatOps.

Identity & access

Settings → Access (RBAC) admin

Roles are viewer / operator / admin, mapped from your IdP groups. The gateway and console both enforce role on every action.

Security & Elevation viewer

Your account: MFA enrollment and sessions, plus requesting a time-bounded promotion to admin. Elevations (admin) is where those just-in-time requests are approved.

Tenants admin

Create and isolate tenants; tenant-scoped agents, policies, and audit stay separated, and tenant-scoped tools enforce a data boundary.

Integrations & compliance

Integrations & Notifications admin

Forward audit to your SIEM (Splunk and others), fire webhooks on events, and route alerts to ChatOps. Notifications controls per-event channel routing and subscriptions.

Compliance admin

One-click evidence export mapped to SOC 2, ISO, GDPR, EU AI Act, and NIST — built from the audit, policy, ownership, and attestation data you already hold.
