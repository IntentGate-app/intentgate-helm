IntentGate · Getting started

Operator journey

The console is installed and you're signed in. This walks you through the five stages — the same ones shown in the Journey bar at the top of every page — to take your agents from undiscovered to governed and provable.

1 Install 2 Discover 3 Govern 4 Attest 5 Prove

The Journey bar in the console highlights which stage you're on, so you can always tell where you are and jump back in.

1Install — done

You're past this one: the gateway, console, and database are running and you've signed in with your IdP. The Journey bar opens on Install. Nothing to do here — move to Discover.

2Discover — find your agents

Where
Discovery sources and Agents in the sidebar.
Goal
See every AI agent that touches your tools — including ones nobody told you about.

There are two ways agents appear:

  1. On the gateway — once an agent is routed through IntentGate, every call it makes is observed, and it shows up automatically.
  2. Passive scan (Shadow) — connect your existing sources on Discovery sources (CASB, proxy, DNS, cloud, IdP) so agents calling tools outside the gateway surface as shadow AI. Add a source, or import a CSV/JSON to seed the list.

Open Agents to see the inventory. The metric cards at the top (total, on gateway, shadow, flagged) are clickable filters; use search and the filter chips when the list grows.

Done when: the Agents page lists your real agents, and you can see which are on the gateway vs shadow.

3Govern — own it, set a policy, route it, secure it

Where
Agents → an agent, plus Policy gallery.
Goal
Turn a discovered agent into a governed one — an owner, a policy, routed through the gateway, and locked down.

For each agent, four moves:

  1. Own. Set the owner — must be a company-domain email (enforced), so accountability is real.
  2. Policy. Open the Policy gallery; it recommends a policy for the agent's risk signals. Apply it — that creates a policy draft scoped to the agent. (Need something bespoke? Request a custom policy and the IntentGate team writes it.)
  3. Set up (route). Use Set up on the agent: mint its token, copy the gateway endpoint and the config snippet, and point the agent at the gateway. Now its calls flow through the four checks.
  4. Secure. Apply the network rule so the tool server only accepts traffic from the gateway — this is what stops the agent bypassing IntentGate.

Status moves On gateway · default policy → Policy ready → Governed as calls start flowing under the applied policy. New or ungoverned agents are still held to the baseline floor (destructive tools blocked, money-movement capped), so nothing is wide open while you work through the list.

Done when: your in-scope agents show Governed, each with an owner and a policy.

4Attest — owners confirm what they own

Where
Attestation in the sidebar.
Goal
Owners formally re-confirm their agents on a cadence — your evidence that someone is accountable.
  1. Owners review their queue and attest each agent (confirm it's still theirs, still needed, scope unchanged).
  2. Attesting hundreds one-by-one doesn't scale — run an attestation campaign instead: scope it, and every owner gets their own queue to clear in one pass.

Works with no IGA required, and is ready to sync when you have one.

Done when: the campaign is complete — every in-scope agent has a current attestation from its owner.

5Prove — show the posture

Where
Reports in the sidebar.
Goal
Turn all of the above into evidence for auditors, security, and leadership.

The Reports page produces governance reports — posture, access register, attestation status, and decision activity — viewable in the console and downloadable as CSV / JSON. For automated pulls, the read-only Reports REST API serves the same data.

Done when: you can hand over a current report that shows who owns what, under which policy, attested when, with the gateway's decisions behind it.

From here

The journey loops: as new agents appear (Discover), you govern them (Govern), owners keep attesting (Attest), and the reports stay current (Prove). The Journey bar at the top of every page always shows where you are. For production scaling — multiple gateways, load balancer, Redis — see the Resiliency & HA guide in Resources.
